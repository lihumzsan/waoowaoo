# 角色与目标

你负责从下方的剧本原文中找出所有发生之后会持续影响后文的事件和状态变化，例如身份揭示、关系变化、位置转移、道具得失、规则确立或情绪定调。

这份事件清单之后用来保证故事前后连贯，所以只记录有持续影响的事件，不记录每一个瞬时动作。只输出 JSON。

# 事实来源

- 下方剧本原文是唯一事实来源。
- 不得根据常识或类型片套路，推测原文没有写出的事件。

# 工作规则

- 只记录影响后文连贯性的事件：长期事实、人物状态、关系、场景、道具、世界规则或情绪状态的变化。
- 普通走路、看向某处、短暂停顿、环境氛围等不会持续影响后文的瞬时动作，不要记录。
- 一个事件可以覆盖多句原文，但 sourceStart/sourceEnd 必须精准贴合证据，不要跨进无关剧情。
- sourceStart/sourceEnd 是事件证据对应原文的半开区间 `[sourceStart, sourceEnd)`，按 UTF-16 code unit 计数（即 JavaScript 字符串下标，中文一字一位）。
- eventId 用稳定递增的编号，例如 `event_001`、`event_002`。
- kind 只能使用 `appearance`、`relationship`、`location`、`prop`、`plot`、`rule`、`emotion`，不得创造新类型。
- entities 只写事件直接涉及的对象；entityType 只能是 `character`、`location`、`prop`、`world`。
- persistentFacts 写成事件发生后仍然成立的事实句；如果事件只是一次出场或短暂情绪、没有留下持久事实，输出空数组。
- 只描述事件本身，不要写镜头语言，也不要给事件划分章节或段落。

# 输入

剧本原文：
{{source_document}}

原文长度（UTF-16 code unit）：{{source_length}}

# 输出 Schema

只返回 JSON，不要 markdown，不要解释。

{
  "events": [
    {
      "eventId": "event_001",
      "kind": "appearance",
      "summary": "持续影响剧情的事实或状态变化",
      "sourceStart": 0,
      "sourceEnd": 10,
      "entities": [
        {
          "entityType": "character",
          "entityName": "名称"
        }
      ],
      "persistentFacts": [
        "这个事件之后仍然成立的事实；没有则输出空数组"
      ]
    }
  ]
}

# 自检

- 是否只记录了会持续影响后文的事件。
- 是否没有把瞬时动作、镜头描述或普通气氛写成事件。
- kind 和 entityType 是否只使用允许的枚举值。
- sourceStart/sourceEnd 是否按 UTF-16 code unit 计数的半开区间，且 sourceEnd 大于 sourceStart。
- 每个范围是否满足 `0 <= sourceStart < sourceEnd <= 原文长度`。
- persistentFacts 是否都是事件之后仍然成立的事实。
- 是否严格只输出 JSON。
