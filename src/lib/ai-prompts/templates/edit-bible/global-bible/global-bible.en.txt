# Role and Goal

Read the full script text below and organize the stable facts of this episode: a complete story overview, the main characters, the main locations, the persistent settings, and the overall style tendency visible in the text.

Include only facts the script states or clearly implies. Do not add your own invention. Output JSON only.

# Fact Sources

- The script text below is the only fact source.
- Do not add a name, identity, location, or rule unless the text supports it.
- If one character or location has multiple names, merge them into one entry and put the other names in aliases.

# Rules

- Write synopsis as a complete story overview covering the central conflict, relationships, emotional movement, and the ending (or the current endpoint of the text).
- Output title and logline only when the text provides them or they can be summarized with high confidence. Otherwise omit these fields.
- characters should include only people who recur or affect story understanding. Do not turn one-off generic mentions, background extras, or environmental descriptions into characters.
- Each characters[].voiceProfile must be a structured intrinsic voiceprint profile. It describes only the character's stable voice body, not the current line performance. It must cover age impression, pitch range, timbre color, resonance placement, vocal weight, and surface texture.
- voiceProfile must not include speaking pace, pauses, volume, emotion, sentence-ending treatment, whispering, shouting, crying delivery, or other dynamic delivery states. Those belong to shot performance or line execution, not the character's intrinsic timbre.
- Infer voiceProfile conservatively from source-stated facts or clearly supported identity, age, physical condition, and long-term character presence. Do not reference a specific actor, celebrity, brand, or copyrighted voice.
- locations should include only places that matter for spatial continuity, atmosphere, or story progression. Do not turn ordinary objects or one-off directions into locations.
- entityId must be stable, short, and readable, preferably lowercase words with underscores, for example `character_lin_xiaoyu` or `location_old_house`. Do not duplicate one entity.
- Do not output character offsets or firstSourceStart. Characters and locations may output firstEvidence; the system computes first occurrence positions from block IDs and verbatim quotes.
- firstEvidence.blockId must use a block ID from the input, such as `[p0001]`; firstEvidence.quote must be a verbatim source snippet inside that block. Do not paraphrase, summarize, or add ellipses.
- worldRules should contain only persistent world rules, background facts, constraints, or relationship facts, not one-time actions.
- styleGuide must be inferred from the genre, mood, rhythm, and spatial descriptions in the text. Do not write generic cinematic filler.
- Output only fields listed in the schema below. Do not output anything else.

# Input

Numbered script text blocks:
{{source_document}}

# Self-check

- Is every piece of information grounded in the script text?
- Are characters and locations deduplicated, with aliases merged into one entry?
- Does every main character have an executable, stable, non-celebrity structured voiceProfile?
- Does voiceProfile describe only intrinsic voiceprint traits, without speaking pace, volume, emotion, sentence endings, or situational delivery?
- Are entityId values stable, short, readable, and unique?
- Does firstEvidence use an input block ID, and does the quote appear verbatim inside that block?
- Is styleGuide inferred from the text instead of generic cinematic filler?
- Is the response strictly limited to the schema fields, and JSON only?
