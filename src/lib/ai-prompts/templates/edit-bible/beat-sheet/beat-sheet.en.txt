# Role and Goal

Split the script text below into story beats. A beat is the smallest complete unit of story progress, usually one action, discovery, choice, relationship change, emotional turn, or scene progression.

Your job is only to split and describe these beats. Do not organize them into chapters, and do not design shots. Output JSON only.

# Fact Sources

- The script text below is the only fact source.
- Do not add plot, characters, places, motivations, or endings that are not in the text.

# Rules

- beats must be ordered by sourceStart and must not overlap.
- sourceStart/sourceEnd is the half-open range `[sourceStart, sourceEnd)` of this beat in the text, counted in UTF-16 code units (that is, JavaScript string indices).
- Beat ranges should cover all story-bearing text. Skip only pure formatting, whitespace, or decorative text with no story function.
- Prefer natural story turning points: a new action starts, information is revealed, emotion shifts, a relationship changes, the scene changes, a goal changes, or risk escalates.
- Do not split mechanically by fixed character count, and do not pack a long story passage into one beat.
- estimatedDurationSec is a reasonable screen-duration estimate for this beat as video. A typical beat is 15-45 seconds. Keep complex action or long dialogue within 60 seconds when possible; if it exceeds 60 seconds, split at a natural turn.
- No single beat may exceed 120 seconds, and its text range may not exceed 3,600 UTF-16 code units.
- Merge very short sentences without an independent story change into a neighboring beat.
- persistentFactsIntroduced should include only facts that remain true after this beat and must be remembered later. Do not include momentary actions, atmosphere adjectives, or camera language.

# Input

Script text:
{{source_document}}

Script length (UTF-16 code units): {{source_length}}

# Output Schema

Return JSON only. Do not use markdown or explanations.

{
  "beats": [
    {
      "beatId": "beat_001",
      "title": "short title",
      "summary": "story progression or state change in this beat",
      "sourceStart": 0,
      "sourceEnd": 10,
      "estimatedDurationSec": 30,
      "persistentFactsIntroduced": [
        "fact that remains true after this beat; use an empty array if none"
      ]
    }
  ]
}

# Self-check

- Are beats ordered by sourceStart and non-overlapping?
- Is every sourceEnd greater than sourceStart, and are the offsets UTF-16 code units?
- Does every range satisfy `0 <= sourceStart < sourceEnd <= script length`?
- Did the beat ranges cover all story-bearing text?
- Did you split on natural story turns instead of fixed character counts?
- Is every estimatedDurationSec reasonable, with no beat above 120 seconds?
- Does persistentFactsIntroduced contain only facts that remain true later?
- Is the response strict JSON only?
