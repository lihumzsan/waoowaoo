硬性规则：
- 不得新增、删除或替换任何 shot；draft_video_blocks_json 是新的唯一结构事实。
- 输出的每个 videoBlocks item 必须使用 changed_video_blocks_json 中的 blockIndex 与 shotNumbers，shotNumbers 顺序必须完全一致。
- previous_video_blocks_json 只作为旧提示词、风格和连续性参考；不要机械拼接旧 prompt。
- 用户只能调整相邻片段的边界；所有 shotNumbers 必须保持原始 shotNumber 顺序，不得重排。必须按 draft_video_blocks_json 内的顺序写提示词。
- 不得改变剧本事实、主体身份、场景关系、动作因果、对白/旁白/画外音和音效事实。

- 中文流程中 reason 与 prompt 必须整体使用中文自然语言；除角色名、专有名词、模型字段名和原文台词外，不要输出英文句子。

reason 写作规则：
- 用一句话说明这个手动编排后的视频片段为什么可以作为一个生成片段。
- 如果片段包含被移动进来的分镜，必须说明它与左右相邻分镜的动作、空间、情绪或声音衔接依据。

prompt 写作规则：
- 写成一个完整连续视频片段的最终提示词，不是分镜摘要列表。
- 开头写整体类型、摄影质感、色彩、光线、画面滤镜、声音滤镜、运动节奏、主体连续性和画幅。
- 必须使用 “[00:00-00:03] 镜头1 / [00:03-00:07] 镜头2” 这类时序组织方式；时间范围根据 changed_block_shots_json 中 durationSec 按当前片段顺序累加计算。
- 每个镜头段必须按“运镜或切换方式 + 主体动作与表情 + 位置或空间变化 + 音频信息”组织，并说明与前后镜头的动作惯性、视觉连续或转场逻辑。
- 如果相邻分镜在主体、方向、光线或空间上不同，必须写出可生成的连接方式，例如匹配剪辑、甩镜、推进揭示、运动模糊衔接、光线扫过、声音引导切换、遮挡转场或同方向运动衔接。
- 必须包含声音约束：只生成剧本已有对白/旁白/画外音和音效，不要生成 BGM、背景音乐、持续配乐、完整旋律、歌曲结构、循环鼓点、歌词、人声演唱或音乐段落。
- 如果剧本没有对白、旁白或画外音，prompt 才写“仅保留音效”，不要凭空添加人物说话、解说或配音。
- 默认加入约束：保持无字幕，避免任何文字或字幕，不要生成 Logo，不要生成水印。
