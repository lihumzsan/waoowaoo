# 剧本统一提取

## 作用

当当前目标明确需要结构化剧本分析时，把从零生成、用户粘贴、文件导入或再次修订的剧本整理成同一种 `canonical_screenplay` 语义。用户原文可以先作为普通文字 Resource 直接保存，本 Skill 不是保存、确认或建立“正式剧本”的门槛。来源不同只记录在 `source`，不改变实体、场景和引用结构，也不增加“已确认”“待提取”等工作流状态。

## 实体登记

- 穷尽登记剧本中需要稳定身份的角色、地点和独立道具。出现次数不是登记门槛：只出现一次但真实承载画面动作或关键剧情的实体同样登记。
- 地点按发生画面动作的独立视觉空间登记，不按地名或地理归属合并。同一地理位置中空间形态明显不同、各自发生剧情动作的区域（如山顶悬崖边与坠落后的崖底）必须分别登记为地点实体；空间关系写入 `description`，不得把另一个动作空间降级为已登记地点的“延伸空间”。
- 只被对白、旁白或心理活动提及而没有画面动作发生的地点，转场一闪而过的路过空间，以及同一空间内仅机位、朝向或景别不同的画面，不登记为独立地点。
- `canonicalName` 使用剧本中最清楚、最稳定的名称；别名放入 `aliases`，不要把同一实体拆成多个条目。
- 只登记剧本事实。不得补做服装、造型、场景美术或生图 Prompt，也不得因为预计要生成图片而改写实体范围。
- 群众、背景路人和不具备独立身份的一次性环境物不自动升级为资产实体。
- Worker 不创造数据库 ID。严格按输出契约使用名称引用，稳定 ID 由服务端确定性编译。

## 场景与引用

- 按正文发生顺序划分真实时空单元；每个场景给出准确的 UTF-16 `sourceStart` 与 `sourceEnd`，范围必须落在 `screenplayText` 内且互不重叠。
- 地点或时间发生实质转移即构成新的时空单元。时间连续的连贯动作（如坠落、追逐）跨越两个已登记地点时，必须在空间转移处切分场景，让每个场景引用动作真实发生的地点。
- 每个场景引用一个已登记地点，并穷尽引用该场实际出现的已登记角色和独立道具。
- 引用必须使用对应实体的 `canonicalName` 或已登记别名；不得临时写入未登记名称。
- 不把场景引用理解为生图任务。它只表达剧本事实和后续可追踪关系。

## 两种入口

- 从零创作时，先使用故事开发方法完成剧本，再在同一个 Creative Task 内执行本 Skill 的登记与引用检查。
- 用户已有剧本且 Primary 明确请求本结构化分析时，不重写其创作选择；从精确来源 Revision 规范化文本、实体、场景范围与引用。只有明显无法判定的事实才进入 `openQuestions`。
- 两种入口必须返回同一个 `canonical_screenplay` 契约，不能产生额外状态或第二份剧本。

## 边界

本 Skill 不做资产外观设计、不生成资产 Prompt、不采用 Style Bible、不维护完整状态变化台账，也不决定 Chapter。连续性分析和必要状态变化属于可选的 `continuity_analysis` 或 Bible 能力。

## 自检

- 同一实体是否只登记一次，别名是否无歧义？
- 同一地理名称下发生画面动作的不同空间是否已分别登记，并被各自的场景引用？
- 每个场景范围是否真实对应正文，顺序正确且不重叠？
- 所有场景引用是否都能解析到登记实体？
- 是否误把资产设计、风格、完整状态台账或工作流状态写进了规范化结果？
