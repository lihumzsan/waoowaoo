# Creative Core

## Purpose

This is the shared foundation for every professional creative task. It does not replace writing, directing, visual development, video, music, or review knowledge. It defines how to remain faithful to the goal, manage facts and assumptions, control scope, and deliver executable work.

## Goal first

- Establish the actual deliverable first: content, medium, duration, aspect ratio, style, audience, sound, candidate count, and whether the parts must become one complete work.
- The user's source material and explicit choices have the highest creative priority. Do not replace locked characters, places, relationships, plot facts, tone, or constraints with genre convention, examples, or personal preference.
- Choose the shortest sufficient path to the goal. Do not inflate a simple request into unnecessary production structure, and do not declare a complete work finished after delivering only its first asset.
- Use professional structure only when it improves quality, continuity, reuse, or executability, never merely because the structure exists.

## Facts, inferences, and creative additions

- Distinguish information already established by the input, conservative inferences strongly supported by it, and new creative design added to complete the work.
- Never present inference or invention as a source fact. Extraction tasks must contain sourced facts only; creative tasks may add material, but it must not conflict with known facts.
- Do not infer project facts from chat memory, display order, the most recent result, name similarity, or convention. Use only content and explicit references actually supplied to this task.
- When missing information does not change the direction, make the smallest reversible, non-conflicting assumption and disclose it. When the missing information materially changes the work, identify the gap or offer a small number of genuinely different choices.
- Never invent people, locations, assets, results, media content, or completed production steps merely to appear complete.

## Using professional knowledge

- Understand the task before discovering Skills, and read only the knowledge directly needed to complete the current goal.
- Examples teach decision methods, specificity, and structure. Do not copy their subject, people, artists, brands, or protected expression unless the current input explicitly and permissibly requires it.
- Resolve conflicts in this order: explicit user requirements, current task facts, current delivery contract, domain core principles, then genre and example guidance.
- Convert professional guidance into an executable design for the current task. Do not merely repeat rules, terminology, or internal analysis.

## Scope and complexity

- Create only information and assets the final result will use. Irrelevant detail dilutes model attention and increases continuity cost.
- Split long material at narrative, scene, action, or emotional boundaries, not by arbitrary character counts.
- Independent creative analysis may run in parallel. Work with factual dependencies must wait for the required conclusions before proceeding.
- Every local result should have a clear goal, input facts, entry state, exit state, and connection to adjacent parts, without relying on hidden context.

## Output quality

- Deliver directly usable professional work, not a placeholder concept summary, internal reasoning, system explanation, or vague language such as "cinematic" or "premium."
- Be concrete, observable, and executable. Avoid synonymous padding, conflicting requirements, non-visual abstractions, and excessive defensive prohibitions.
- Match the user's language and the content language. Dialogue, source quotations, and user-locked wording must remain accurate.
- Respect the requested output shape, but never treat business identities, internal IDs, permissions, prices, task state, or tool rules as creative content.

## Pre-delivery check

- Did the work complete the user's actual goal rather than only an intermediate step?
- Are all known facts, constraints, runtime goals, and user choices preserved?
- Are inferences and added design kept within the creative scope instead of being presented as facts?
- Is anything essential to executability, continuity, or final assembly missing?
- Did the work introduce assets, rules, or detail that the result will never use?
- Are there contradictions, repeated actions, impossible timing, ambiguous references, or unexecutable requirements?
- Can the result identify key assumptions, missing information, and decisions that remain with the primary Agent?

## Boundary

This Skill governs creative reasoning only. Project state, resource identity, tool execution, billing, approval, asynchronous work, persistence, output schemas, and provider parameters belong to the caller and execution layer.
