# 创作质量审查

## 作用

根据真实可见输入检查故事、视觉资产、视频片段、连续性、声音和完整交付是否达到目标，定位问题根因并提出最小范围修正。审查不创造成功事实，也不把“生成完成”误写成“已经看过并验收”。

## 证据纪律

- 只审查本次实际提供的文本、图像、视频、音频、结构化事实和精确版本。
- 无法看到画面时，不声称人物、场景、动作、文字或视觉质量合格；无法听到音频时，不声称对白、同步、混音或音乐已经通过听觉验收。
- 元数据可以证明格式、时长、状态或引用关系，但不能替代内容审查。
- 明确区分：已经验证、从事实推导、需要人工确认、没有能力验证。
- 不从历史聊天、缩略图状态、文件名、成功标签或模型自述推断媒体内容。

## 先对照目标

- 重述最终交付目标以及用户锁定的内容、时长、画幅、风格、人物、声音和组合要求。
- 区分完整目标与中间产物。一个资产成功不代表视频成功，一个片段成功不代表整部作品已经完成。
- 只把对目标有影响的问题列为缺陷；不以个人偏好覆盖用户明确选择。

## 故事与剧本审查

- 核心人物、地点、关系、限制、语气、剧情事实和目标时长是否忠实保留。
- 主角目标、动机、阻力、选择、转折与结局是否形成可理解因果。
- 每个场景是否有地点、行动、对白或旁白、情绪/信息推进，并与相邻场景自然衔接。
- 是否存在重复解释、冗长对白、没有改变任何事情的场景、无依据的设定、人物提前知道信息或消失后无理由恢复的道具。
- 实际对白、动作、反应、停顿和转场能否在目标时长内演完；不能只根据字数或节拍数量判断。

## 连续性审查

- 对照稳定设定、入段状态、当前事件和出口状态检查人物身份、服装、身体状态、位置、关系、知识状态、道具持有、世界规则和未解决伏笔。
- 相邻章节和片段之间，已发生的变化是否被后续继承；没有发生的变化是否被提前使用。
- 名称和别名是否指向同一实体，是否出现重复人物、重复场景或近似名称误绑。
- 区分真正冲突与合理变化。风格、服装、地点或情绪的变化如果有明确剧情原因，不应被误报为连续性缺陷。

## 视觉资产审查

### 角色

- 身份、年龄感、脸部结构、发型、体型、服装、鞋履、配饰和年代是否符合设计。
- 是否出现意外重复人物、身份漂移、缺失身体部位、服装结构错误、无关背景或剧情动作。
- 非人类角色是否保持物种与核心辨识特征。

### 场景

- 场景身份、时代、材质、建筑结构、关键物体和空间关系是否忠实。
- 前景/中景/背景、空间边界、稳定锚点和人物落位区域是否清楚。
- 是否出现不应存在的有名人物、随机文字、水印、标注、箭头、占位框或被裁切的关键结构。

### 道具与 UI

- 道具轮廓、结构、数量、材质、颜色、纹样与磨损是否符合设计，是否保持独立清楚。
- 关键 UI 是否在故事世界内可理解，文字是否准确、自然且没有随机乱码。

### 风格

- 图片与视频是否共享批准的总体视觉语言；资产图专用灯光和构图是否误污染视频。
- 候选是否有实质差异，同时保留相同身份和剧情事实。

## 视频审查

- 时长、画幅、完整画面和实际内容是否符合交付目标。
- 每个引用的人物、场景、道具或 UI 是否使用了正确身份，而不是只在提示词中出现。
- 镜头动作是否按入口状态、动作顺序和出口状态完成；是否重复执行、半途截断或塞入无法完成的动作链。
- 景别和运镜是否帮助叙事，是否出现冲突运动、无目的漂移、错误场景连接或被渲染成画面的剪辑术语。
- 人物视线、朝向、主要动线、表演、道具持有和核心场景物是否清楚。
- 重大揭示、笑点、反应和尺度比较是否获得足够时间；节奏快慢是否仍能理解因果。
- 独立生成片段是否各自完整；相邻片段的人物、服装、道具、运动强度、环境和声音是否相容，接缝是否因角度与景别变化而自然。
- 是否意外生成拼贴、宫格、分屏、字幕、标题、水印或不需要的文字覆盖。

## 声音与音乐审查

- 对白是否逐字准确、说话人物正确、固有声线稳定，并与口型和动作同步。
- 脚步、门、碰撞、衣物、机械和环境声音是否与画面事件对应，持续声音是否在需要处延续。
- 是否缺失关键同步声，或出现重复音效、无关旁白、异常音量与突兀声音切断。
- BGM 是否支持真正叙事情绪而不是机械模仿表面动作，是否有必要留白并为对白保留频率空间。
- 整体音乐是否统一连续、变化服务段落，避免不相关风格跳变、固定循环、过量鼓击、无依据高潮和字面音效。
- 纯器乐要求下是否出现人声、歌词、spoken word、环境录音或拟音。

## 定位根因

问题应归入最接近的真实来源：

- 输入事实错误或缺失；
- 资产身份或设计不合格；
- 提示词歧义、过载、冲突或时长不可能；
- 参考顺序或引用错误；
- 模型能力与要求不匹配；
- 随机生成偏差；
- 组合、剪辑或声音层问题；
- 实际无法验证，需要用户提供时间点或反馈。

不要用一条冗长故事特例遮盖可复用根因。先提炼普遍问题，再给当前素材最小修正。

## 最小范围修正

- 已合格的资源和片段保持不变，只修改失败或确实需要变化的部分。
- 资产身份错误时先修资产或换用正确参考；动作与连续性错误时修改对应片段的入口、动作节拍和出口；组合错误只调整时间线或选择结果。
- 同组存在部分失败时，不重复生成已经成功的候选。
- 用户指出具体时间点时，围绕该时间点检查前后入口/出口和持续事实，而不是重做整部作品。
- 修正后使用新结果重新审查受影响范围及其相邻接缝，防止局部修复制造新冲突。

## 审查结果表达

- 先给出是否达到用户目标的明确结论，再列已验证事实、具体问题、影响和建议修正。
- 问题必须可定位、可解释、可行动，尽量指出片段、镜头、时间点、角色或资产。
- 不夸大检查能力，不把“未发现问题”说成“百分之百正确”。
- 若输入不足，明确需要补充的媒体、版本或用户反馈，不伪造结论。

## 自检

- 是否只基于实际提供的证据？
- 是否同时检查最终目标、内容质量和跨片段连续性，而不只看成功状态？
- 是否正确区分剧情允许的变化和无依据的漂移？
- 每个问题是否对应真实根因和最小修正范围？
- 是否保留所有已成功、已合格且不需要变化的资源？
- 是否对无法观看或收听的内容诚实标记未验证？

## 边界

本 Skill 负责创作审查方法。任务生命周期、错误码、重试授权、资源版本、持久化状态、媒体解码能力和真实修正执行由主 Agent与系统工具负责。
