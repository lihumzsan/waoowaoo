# 视觉风格开发

## 作用

把故事事实、用户要求与已有视觉上下文转化为一套可供图片和视频共同使用的视觉风格契约，并在需要时提供有实质差异的风格候选与预览方向。本 Skill 只负责视觉风格，不负责角色、场景、道具的具体资产设计。

## 输入顺序边界

- 风格可以先于剧本从用户创意简报产生，也可以在已有 `canonical_screenplay` 后产生或修订；两种顺序使用同一 Style Bible 契约。
- 不要求为了生成风格先生成剧本，也不要求为了生成剧本先生成风格。只消费调用方显式提供的事实与精确 Revision，不读取“最新”或“刚才那份”内容。
- Style Bible 不改变剧本实体，canonical screenplay 也不拥有视觉风格；两者只在资产设计、视频设计等明确消费者处组合。

## Style Bible 字段职责

- `rawUserStyle` 保存用户原始风格意图；它是来源事实，不是经过整理的生成约束。
- `styleSummary` 方便用户理解和比较视觉方向，不直接作为生成约束。
- `visualStyle` 是图片和视频共享的总体画面风格，必须把美术媒介、画面滤镜、总体质感和色彩基调整合成一段具体、可执行的描述。
- `assetImageStyle` 只供角色图、场景图、道具图和风格预览图等资产图片使用：
  - `lighting` 规定资产图片的风格化光线表达；
  - `texture` 规定资产图片的材质和细节质感。
- 角色、地点和道具的固定资产图版式由生图执行 policy 按 schema 唯一追加，不属于 Style Bible。
- 视频生成只消费 `visualStyle`，绝不继承 `assetImageStyle` 的灯光或材质细化。
- Style Bible 是视觉风格的唯一权威；资产设计只能消费它，不能根据单张参考图或单个资产重新定义项目风格。

## 视觉风格边界

- 视觉风格只决定美术媒介、画面滤镜、总体质感和色彩基调，不替导演决定叙事视角、表演、信息节奏、焦段、运镜、视频剪辑或声音。
- `visualStyle` 不写灯光、构图、焦段、运镜或声音；这些分别属于资产图片政策、导演、视频或声音设计。
- 区分跨图片与视频共享的总体视觉风格，以及只供资产图片使用的灯光和材质细节。任何资产专用规则都不能被误写为跨媒体总体风格。
- 风格摘要方便人理解；真正用于生成的风格描述必须具体、可执行，不能只写“电影感”“高级”“梦幻”等抽象评价。
- 导演、影片、工作室、流派或年代引用应转写为可执行的媒介、材质、色彩、轮廓、细节密度和画面处理特征，不依赖受保护名称本身。
- 用户明确选择的风格和已确认项目 Style Bible 高于参考图片的原始画风。参考图可以提供身份、结构和材质事实，不能覆盖明确的美术方向。

## 风格候选

- 多个风格候选必须忠于同一剧情、角色、地点、道具和时间事实。
- 候选应在美术媒介、总体质感、色彩与设计语言上形成实质差异，而不是只做轻微调色。
- 每个候选都必须形成完整、自洽、可直接执行的 Style Bible，而不是标题加几条抽象形容词。
- 候选差异不能通过改变人物身份、场景事实、故事内容、年代或事件来制造。
- 用户已经明确要求某种风格时，候选只能探索该要求允许的合理范围，不能把明确要求降级为可选建议。

## 灵感素材库

素材库用于拓展检索与组合空间，不是封闭枚举，也不能把标签原样堆进最终输出。先锁定用户或剧本事实，再从相容维度中选择少量组合；候选至少在两个维度有实质差异，其中一个来自媒介或设计语言。

- 主要媒介与制作表面：实拍写实、纪实、传统手绘二维、数字二维、赛璐璐、定格、黏土、木偶、剪纸、皮影、沙动画、油画、水彩、水墨、粉笔、玻璃绘制、像素、矢量、版画、木刻、低多边形、体素、玩具模型、毛毡、纸艺、布偶、三维 CG、卡通渲染、转描、真人动画混合、拼贴。
- 造型与设计语言：极简线稿、几何扁平、怪诞卡通、暗黑童话、写实动漫、欧式绘本、美式卡通、日式动漫、中国美术片、国潮、装饰艺术、新艺术、包豪斯、构成主义、粗野主义、复古未来、赛博朋克、太阳朋克、蒸汽朋克、Y2K、Vaporwave、Dreamcore、Weirdcore、Cottagecore、Dark Academia。
- 色彩与全局影像处理：黑白、高反差灰阶、单色、双色、去饱和、低饱和高级灰、高饱和糖果色、粉彩、大地色、冷暖对比、青橙、红黑、银蓝、紫粉霓虹、褪色怀旧、胶片颗粒、即时成像、VHS、DV、CCD、Hi8、柔焦、光晕、色差故障、雾面低对比、锐利数码。
- 只进入 `assetImageStyle.lighting`：自然光写实、高调、低调、明暗对照、硬光、柔光、轮廓光、顶光、侧逆光、窗光、舞台光、霓虹光、荧光灯、钠灯、黄金时刻、蓝调时刻、雾化光、无影棚拍。任何光源和时间词都必须与已有事实兼容。
- 只进入 `assetImageStyle.texture`：赛璐璐平涂、黏土指纹、木偶接缝、纸纤维、皮影纤维、砂粒、油画厚涂、水彩渗化、水墨晕染、粉笔粉尘、像素硬边、矢量平面、版画压痕、木刻刀痕、低多边形折面、玩具表面、毛毡绒毛、折纸折痕、布偶织物与缝线。
- 语义灵感只作相容性筛选：现实主义、自然主义、新现实主义、诗意现实主义、魔幻现实主义、超现实主义、表现主义、印象主义、象征主义、极简主义、极繁主义、黑色电影、公路电影、武侠、犯罪、恐怖、浪漫、怀旧、梦幻、疏离、粗粝、荒诞、怪诞、史诗。只有能转成单帧可见的媒介、轮廓、色彩、材质或影像处理时才写入 Style Bible。

合并同义风格族后再组合，禁止仅用近义名称制造候选差异。导演、影片、工作室、年代或地域名称必须转译成可执行视觉属性，且不能据此新增故事世界事实。

## 风格预览

- 风格预览服务于比较视觉方向，不是新的剧情版本或资产事实来源。
- 预览画面必须使用对应候选的 `visualStyle` 与 `assetImageStyle`，不能混用其他候选的灯光或材质。
- 预览可以选择关键故事画面展示风格适配性，但不得借预览改变人物身份、场景事实、道具状态或剧情内容。
- 预览中的偶然构图、姿态、光线细节和生成瑕疵不自动成为 Style Bible 或资产事实。

## 与资产设计的接口

- 本 Skill 决定跨媒体视觉政策和资产图片政策；角色、场景、道具的稳定外观与空间结构由资产设计负责。
- `assetImageStyle.lighting` 规定资产图共同使用的风格化灯光。场景自身真实存在的物理光源、位置、时间和照明条件属于场景事实，由资产设计提供。
- 最终资产图片提示词应把稳定资产事实与已确认 Style Bible 合成；不能把风格化灯光或滤镜写回角色或地点的稳定身份描述。固定版式由执行 policy 追加。
- 参考图画风与 Style Bible 冲突时，保留参考图支持的身份、轮廓、结构和材质事实，并以 Style Bible 为最终画面风格。

## 自检

- `visualStyle` 是否只包含跨图片与视频共享的媒介、滤镜、总体质感和色彩？
- `assetImageStyle` 是否只包含资产图专用灯光与材质，没有固定版式？
- 是否把抽象风格名称转成了可执行视觉特征？
- 多个候选是否具有实质差异但仍忠于相同故事事实？
- 风格预览是否只用于比较，而没有创建新的剧情或资产事实？
- 是否避免让单张参考图重新定义已确认的项目风格？

## 边界

本 Skill 负责 Style Bible、风格候选与风格预览的专业方法。角色、场景、道具和参考资产的具体设计由资产设计 Skill 负责；导演、镜头、视频、声音与配乐由对应 Skill 负责。输出 Schema、候选数量、预览网格版式、资产图固定版式、图片画幅、provider 参数、真实人物安全策略和最终生成后缀由调用方与执行层定义。
