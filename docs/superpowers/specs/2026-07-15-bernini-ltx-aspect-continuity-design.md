# Bernini 与 LTX 视频画幅连续性设计

## 背景与结论

同一段小说推文中，LTX 与 Seedance2 Bernini 480P 生成的视频会连续放入剪映。当前实测文件尺寸不一致：LTX 为 `1280×704`，Bernini 为 `832×480`。Bernini 的宽高比更窄，因此在宽屏画布上出现明显左右边框，两个镜头相接时也会产生画幅跳变。

本次采用以下方案：

- 保持 LTX 工作流及其实际 `1280×704` 输出不变。
- 仅将横屏 Bernini 的原生生成尺寸调整为 `848×464`。
- Bernini 的输入图预处理和模型条件画布统一使用精确的 `53:29` 比例，继续采用裁切填满，不制造左右黑边。
- 最终成片仍由剪映统一导出分辨率；应用内不增加二次转码。
- 不迁移或重写现有媒体。用户会重新运行需要使用的 Bernini 图片/视频。

## 现状证据

| 来源 | 实际 MP4 尺寸 | 宽高比 | 结果 |
| --- | ---: | ---: | --- |
| LTX2.3 Goon First/Last Frame | `1280×704` | `1.8182`（`20:11`） | 宽屏内容铺满 |
| Bernini 480P I2V（当前） | `832×480` | `1.7333` | 相对 LTX 明显偏窄，产生左右边框 |
| Bernini 480P I2V（目标） | `848×464` | `1.8276`（`53:29`） | 与 LTX 的相对比例差约 `0.52%` |

`848×464` 的两边都能被 16 整除，最长边不超过 Bernini 当前的 848 上限，并且比 `832×480` 更接近 LTX 的实际画幅。剪映统一缩放到项目画布时，约 `0.52%` 的比例差只会造成极小的边缘裁切，不应形成肉眼可见的左右边框或画幅跳变。

## 目标

1. 新生成的横屏 Bernini 视频接近 LTX 的实际画幅，连续剪辑时不出现明显的画面宽窄跳变。
2. Bernini 最终 MP4 的像素内容铺满输出画布，不烘焙左右黑边。
3. 输入图裁切比例、模型条件尺寸和最终视频尺寸保持一致，避免工作流内部再次加边或变形。
4. 只影响 Bernini 横屏请求，不改变 LTX、Bernini 竖屏及其他比例的现有行为。

## 非目标

- 不把 LTX 改为标准 `16:9`，也不改变其工作流节点或现有生成质量。
- 不要求两个模型直接输出相同的像素分辨率；剪映负责最终分辨率统一。
- 不在服务端加入 FFmpeg 补边、裁切或重编码步骤。
- 不修改浏览器视频卡片的 `object-contain` 预览方式。
- 不批量迁移数据库记录，不重写已生成的 Bernini 文件。

## 设计

### 1. Bernini 横屏尺寸解析

在 `src/lib/generators/comfyui-video.ts` 中保留通用画幅表供 LTX 和其他工作流使用，但为 Bernini 增加明确的横屏规则：当项目请求 `16:9` 横屏时，传给 Bernini 工作流的尺寸必须是 `848×464`，不能再由通用的 `1280×736` 比例缩放为 `832×480`。

Bernini 竖屏及非横屏比例继续使用现有的 480 短边、848 长边上限和 16 像素对齐逻辑。本次不扩大其他比例的行为范围。

### 2. 输入图预处理与条件画布一致

在 `src/lib/providers/comfyui/workflow-registry.ts` 的 Bernini 控制注入中，对 `848×464` 使用精确比例，而不是复用会把相近比例吸附成 `16:9` 的模糊格式化结果：

- 节点 `416`（`LayerUtility: ImageScaleByAspectRatio V2`）设置为 `aspect_ratio = custom`。
- 同一节点设置 `proportional_width = 53`、`proportional_height = 29`。
- 保持 `fit = crop`、`method = lanczos`、`round_to_multiple = 16`、`scale_to_side = longest`。
- 节点 `417` 的最长边设置为 `848`。
- 节点 `384`（Bernini conditioning）的 `width`、`height` 设置为 `848`、`464`。

仓库内同类 Bernini 工作流节点已经使用 `custom` 模式，因此该表达方式属于现有节点合同。禁止只设置 `aspect_ratio = 16:9`：那会让预处理裁切比例与 `848×464` 条件画布不一致。

### 3. 数据流

横屏项目的 `videoRatio = 16:9` 经 worker 作为 `aspectRatio` 传给视频生成器。视频生成器识别 Bernini 模型后解析为 `848×464`，再将该尺寸注入工作流。工作流注册层把同一尺寸写入图像预处理、最长边控制和 Bernini conditioning。ComfyUI 直接输出该画布上的 MP4，应用按原文件保存，不做后处理。

### 4. 剪映交付方式

剪映项目采用一个统一的横屏画布和统一导出分辨率。LTX `1280×704` 与 Bernini `848×464` 都按“填充画布”的方式缩放；由于两者画幅差低于 1%，Bernini 只需要极小的边缘裁切。旧 Bernini 素材不做自动修复，重新生成后替换即可。

## 失败保护

- 如果工作流解析后，节点 `416` 不是精确 `53:29` 的自定义裁切，视为失败，不能以“尺寸已修改”作为完成依据。
- 如果节点 `384` 的条件尺寸与预处理目标不一致，视为失败。
- 如果真实生成的 MP4 不是 `848×464`，或像素画面仍包含烘焙的左右黑边，必须继续定位 ComfyUI 节点行为，不能退回服务端补黑边方案。
- 所有新尺寸仍需满足 16 像素对齐及 Bernini 848 最长边限制。

## 测试策略

实现遵循测试先行：先加入会失败的断言，再修改生产代码。

1. `tests/unit/generators/comfyui-video.test.ts`
   - 新增横屏 Bernini 用例，断言 `16:9` 请求向工作流客户端传入 `848×464`。
   - 保留并验证现有竖屏 Bernini 尺寸行为。
   - 增加或保留 LTX 回归断言，确认其尺寸传递不受影响。
2. `tests/unit/providers/comfyui-workflow-registry.test.ts`
   - 断言横屏 Bernini 节点 `416` 使用 `custom`、`53`、`29` 和 `crop`。
   - 断言节点 `417` 为 `848`，节点 `384` 为 `848×464`。
   - 断言音频与非音频 Bernini 工作流都遵循同一尺寸合同。
3. 定向验证
   - 运行上述两个 Vitest 文件。
   - 运行 TypeScript 类型检查。
4. 真实链路验证
   - 实际重新生成一条横屏 Bernini 视频。
   - 读取最终 MP4 元数据，确认 `videoWidth = 848`、`videoHeight = 464`。
   - 抽查首帧或播放画面，确认没有烘焙的左右黑边。
   - 与一条 LTX 视频相邻放入剪映，确认使用填充画布时没有可见画幅跳变。

## 验收标准

- 新的横屏 Bernini 最终 MP4 为 `848×464`。
- Bernini 与 LTX 实际宽高比的相对差不超过 `1%`。
- Bernini 像素画面没有烘焙的左右黑边。
- LTX 工作流和输出行为不变。
- Bernini 竖屏及其他比例没有回归。
- 不引入服务端视频转码，也不修改历史素材。

## 回滚

代码回滚只需恢复 Bernini 的尺寸解析和工作流比例注入逻辑。由于没有数据库迁移、文件重写或输出后处理，回滚不会影响已有素材；已经生成的 `848×464` 文件仍可由剪映正常使用。
