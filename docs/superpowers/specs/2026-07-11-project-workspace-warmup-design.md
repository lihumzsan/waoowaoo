# 项目工作区深度预热设计

## 目标

保持完整开发功能不变，把“蛊真人后传”首次进入工作区时的页面编译、项目数据、默认剧集配置和运行状态查询前移到 `npm run dev` 启动阶段。

## 方案

扩展现有登录态预热程序：

1. 登录 tigli 并请求项目列表。
2. 从返回结果按名称查找“蛊真人后传”，动态取得项目 ID，不硬编码数据库 ID。
3. 请求项目工作区页面和项目数据接口。
4. 从项目数据中选择排序后的第一个剧集作为默认剧集。
5. 预热带 episode 参数的工作区、剧集 `profile=config` 接口，以及对应的 `/api/runs` 查询。

所有请求均为 GET；除既有登录 POST 外不产生业务写入。项目或剧集不存在时只记录跳过信息，预热程序正常退出，其他服务继续运行。

## 验收

- 完整 `npm run dev` 中深度预热全部返回 200。
- 重启后真实访问“蛊真人后传”不再触发 10 秒级工作区编译和首次 API 编译。
- 预热后的项目页面、项目数据、剧集配置和运行状态接口分别记录实际耗时。
- 原有首页预热、Worker、Watchdog、Bull Board 和生产启动行为保持不变。
