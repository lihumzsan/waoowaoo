# 视频工具自由配音关联项目角色设计

## 目标

修正“视频工具”页面自由配音的音色来源：用户必须先选择自己拥有的项目，再选择该项目资产库中的角色，并使用角色已配置的参考音色生成临时配音。

生成结果仍是视频工具级临时产物，仅在 Redis 中保存一天；本次不恢复已经移除的项目自由配音数据库历史。

## 已确认的产品决策

- 自由配音表单增加“关联项目”和“角色参考音色”两个选择项。
- 角色列表严格来自所选项目资产库，不再读取或兜底到全局音色库。
- 项目内所有角色都展示。
- 未配置参考音色的角色显示为“角色名（未配置参考音色）”，但不可选择。
- 切换项目时立即清空当前角色选择，防止跨项目沿用旧角色。
- 不增加配置跳转、自动修复、试听按钮或其他额外交互。
- 生成结果展示项目名和角色名，明确本次配音的来源。

## 页面与数据流

`FreeVoiceToolCard` 继续作为视频工具页面中的独立卡片：

1. 页面通过现有 `GET /api/projects` 读取当前用户的项目。
2. 选中项目后，通过现有统一资产接口 `GET /api/assets?scope=project&projectId=<id>&kind=character` 读取项目角色。
3. 项目未选择时，角色选择器禁用并提示先选择项目。
4. 项目切换时清空角色；资产加载期间角色选择器保持禁用。
5. 只有同时存在文本、项目以及带参考音色的角色时，生成按钮才可用。
6. 提交请求只包含 `text`、`projectId` 和 `characterId`，不允许客户端提交任意参考音频 URL。

桌面端将项目和角色选择器并排展示，窄屏下自然换为上下排列，保持现有卡片的信息密度和视觉体系。

## 服务端契约与安全边界

`POST /api/video-tools/free-voice` 请求调整为：

```json
{
  "text": "需要朗读的文字",
  "projectId": "project-id",
  "characterId": "character-id"
}
```

服务端按以下顺序处理：

1. 校验用户登录态和三个必填字段。
2. 查询用户拥有的项目及其小说推文配置。
3. 校验角色确实属于该项目，拒绝跨项目角色 ID。
4. 校验角色存在 `customVoiceUrl`；缺失时明确失败，不回退到全局音色或默认样本。
5. 使用项目配置的 `audioModel`；项目未配置时沿用现有单模型解析规则。
6. 创建 Redis 临时记录并提交语音队列任务。

队列任务的 `projectId` 使用真实项目 ID，不再使用固定的 `video-tools` 占位值。任务 payload 仍只保存生成所需的文本、参考音频快照和解析后的模型，不创建数据库任务历史。

## 临时记录

`VideoToolFreeVoiceRecord` 增加来源快照：

- `projectId`
- `projectName`
- `characterId`
- `characterName`

这些字段随 Redis 记录一起保存一天，用于结果展示和轮询，不引入 Prisma 迁移。旧的 Redis 记录仍可读取；新字段在解析时保持兼容可选，旧记录继续使用已有 `voiceName` 展示。

## 错误处理

- 无项目：角色选择器禁用，生成按钮不可用。
- 项目无角色：显示“该项目暂无角色”。
- 项目有角色但都无参考音色：角色仍全部可见并标注状态，生成按钮不可用。
- 项目或角色越权、角色与项目不匹配：服务端返回未找到或禁止访问，不泄露其他用户资产。
- 角色参考音色在页面加载后被移除：服务端提交时再次校验并返回明确错误。
- 项目列表、角色列表或提交失败：沿用卡片现有错误区域，不增加弹窗或跳转。

## 测试与验收

自动化测试覆盖：

- 页面不再读取全局音色，并提交 `projectId + characterId`。
- 切换项目会清空角色选择。
- 无参考音色角色可见但不可选择。
- 后端拒绝缺少项目或角色参数。
- 后端拒绝非本人项目、跨项目角色及无参考音色角色。
- 正常提交使用项目角色的 `customVoiceUrl`、项目音频模型和真实项目 ID。
- Redis 一天 TTL、任务轮询和音频下载行为不回归。

功能检查完成后，在真实浏览器中验收桌面和移动端：项目/角色层级清晰，禁用状态可辨识，下拉框、文本框和生成按钮无溢出或错位。

## 非目标

- 不允许从全局音色库选择音色。
- 不修改项目角色的参考音色配置。
- 不恢复数据库自由配音记录或多版本管理。
- 不增加项目搜索、角色搜索、试听、快捷配置或自动跳转。
- 不改动视频拼接工具。
